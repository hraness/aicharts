# Benchmark, calculator and companion assurance

The public comparison product keeps source evidence separate from private usage. Its checks establish admission, transformation, and publication properties; they cannot establish the scientific validity of an external benchmark or the applicability of a hardware throughput estimate.

| Boundary | Maintained evidence | Limit |
| --- | --- | --- |
| Coding snapshot replacement | `scripts/refresh-coding-agents.test.ts`: duplicate row, semantic and series identities; retained rows and metric coverage; regressed retrieval time; model/setting reconciliation; version-aware updates | A newer retrieval time does not prove that the upstream source is current or accurate. |
| Atlas publication | `lib/benchmark-atlas.test.ts`, `lib/benchmark-atlas-data.test.ts`: matching evaluation versions, source-only versus measured coverage, finite bounded scores, cost units, uncertainty meaning, provider/model/harness identity | Scores remain separate cohorts. Missing cost is not a free run. |
| Ranking and frontier | `lib/benchmark-atlas.property.test.ts`, `lib/option-space.property.test.ts`: arbitrary permutations with ties and distinct Unicode identities; independent nondomination predicate; provider ranges | English display collation has an exact UTF-16 tie break. The environment's collation implementation remains a dependency. |
| Calculator inputs and arithmetic | `lib/calculator-inputs-data.test.ts`, `lib/calculator-math.property.test.ts`, `scripts/refresh-calculator-inputs.test.ts`: dated source admission, source/policy custody, rate-change bounds, no write on failed refresh, dimensional integer oracles, token conservation, monotonic costs | Binary64 scenario arithmetic and sampled bounded properties are not an unbounded arithmetic proof. Curated measurements remain assumptions. |
| Published data and discovery | `app/data/benchmark-atlas-json.test.ts`, `lib/benchmark-atlas-view.test.ts`, the existing browser suite: checked snapshot, native units and version in JSON/structured data, admitted URL state, visible chart/table/export journeys | Browser evidence must be collected against the integrated build. Pure data tests alone do not qualify rendered exports. |
| Analytics privacy | `lib/analytics.test.ts`: allowlisted public IDs/actions, discarded calculator values, rejected free-form IDs and raw URL data | This checks the owned capture boundary, not arbitrary third-party browser behavior. |
| macOS companion | `scripts/menubar.test.ts`, the locked native build and desktop adapter tests: explicit prebuilt launch, release admission, managed-directory refusal, private staging, failure exit propagation, fixed browser actions | Disposable local client; no product authority. Filesystem checks assume the user's own processes do not maliciously replace directories between checks. |

Run the narrow tests when changing a boundary, `bun run check:generated` for offline snapshot admission, and `bun run test:property` for the shared laws. `bun run menubar:build` builds the unbundled macOS companion with the committed lockfile. The integration owner runs `bun run check`, including the browser checks, after concurrent lanes converge.

Automated refresh remains the only path for live snapshot values. These assurance changes perform no external source refresh, mutate no user usage data, and add no analytics fields. See [calculator data](calculator-data.md), [analytics instrumentation](analytics-instrumentation.md), and the [desktop rules](../desktop/AGENTS.md) for the corresponding maintained contracts.
