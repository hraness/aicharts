# Local metadata readers

`parse_reader(reader, provider, &namespace_key)` imports an explicitly supplied Codex or Claude Code JSONL stream. `merge_collections` merges copied files and supported Claude streaming revisions before totals are computed. Both return fixed errors; neither opens files, discovers providers, reads credentials, stores data nor sends network requests.

The caller supplies a private 32-byte key. HMAC-SHA256 produces scoped 16-byte event and execution IDs from native metadata. The key is never included in a collection. Use the same key when merging copies of a source; namespace rotation needs a separate migration design. Opaque IDs remain pseudonymous personal data.

## Supported measurements

- Codex `session_meta` and `event_msg/token_count` records with RFC 3339 timestamps and `total_token_usage`. Input includes cached input; the reader subtracts that subset. Reasoning is an output subset and is never summed twice. An initial `last_token_usage` is retained only when it fits within the first cumulative snapshot; preceding unobserved history is explicitly omitted. Without that initial last-usage snapshot, the first total establishes a baseline and contributes no usage. Later unchanged cumulative snapshots contribute nothing.
- A decrease in any Codex cumulative counter stops the remaining chain with a coverage warning. The reader does not guess whether a decrease is compaction, reset, stale data or a new session. Declared fork histories are excluded, including records read before a late fork declaration. Missing lineage cannot establish that an undeclared session is not replayed history. IDs use native session identity and the normalized timestamp; optional turn/event metadata does not change identity. Conflicting same-time events fail rather than receive fabricated line-number identities.
- Claude Code assistant records with `requestId`, `message.id`, numeric `message.usage` and RFC 3339 timestamps. Matching request/message IDs represent streaming revisions. Componentwise-monotonic revisions keep one final usage, even when input order is reversed or files are copied. Incomparable revisions fail; the reader does not synthesize per-field maxima from conflicting snapshots. The latest observed revision timestamp determines the completion bucket.
- Claude input, cache reads and cache creation are separate quantities. Cache creation requires the explicit `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` split whenever its aggregate is positive. Legacy records without a split are omitted with `claude_cache_ttl_unknown`; a TTL is not guessed. This may omit substantial historical Claude coverage until a reviewed unknown-TTL protocol category exists.
- Claude main execution IDs use `sessionId`; sidechain IDs require both `sessionId` and `agentId`. Usage with missing execution metadata can still be retained under its request/message ID, with unknown execution. Different execution attribution for one occurrence is a conflict, not an additional request.

All records have imported evidence, unknown model and auth mode, and an unassigned account. The parser makes no pricing or subscription claims. Historical prompt authorship and precise activity intervals remain unmeasured. No text inspection attempts to distinguish humans, automation, tool results or injected messages. Empty prompt/interval arrays mean unavailable coverage, not a claim of zero prompts or activity.

Claude usage does not report a separate reasoning-token subdivision in this projection. Its `reasoning_output` is zero with an `unmeasured_reasoning` coverage warning; this is not proof of zero thinking tokens. Codex adds the same warning when an examined cumulative total or initial last-usage counter omits `reasoning_output_tokens` or reports it as null. The existing zero fallback and numeric measurements remain unchanged; the warning does not reconstruct missing reasoning counts. Later last-usage counters are not examined. The total output counter remains intact. Any future admission or reporting route must preserve this coverage distinction.

Collections contain canonical, per-UTC-day batches, split at 4,096 records. More than 100,000 physical lines or 100,000 distinct measurements fail. One line is capped at 1 MiB and JSON nesting at 64. Larger valid histories must be supported by a later checkpointed parser that preserves cumulative state; splitting a Codex source arbitrarily changes baseline coverage and is not a supported workaround.

## Privacy boundary

The reader streams from the caller's `BufRead` view of one line instead of copying complete transcript lines. Its deserialized structs contain only numeric counters, bounded native IDs, timestamps and closed record kinds. Serde skips unknown values, including message content, title, model name, path and tool arguments. Native IDs and timestamps exist briefly during normalization; only keyed IDs and normalized numeric timestamps reach the collection.

The process must still read source bytes to find metadata and skip values. Rust, these types and the numeric wire are not an OS-enforced sandbox or a proof of non-exfiltration. A malicious uploader can encode data into numbers. This crate establishes the honest implementation's content-minimization boundary; OS isolation and authenticated admission are separate work.

Synthetic tests change non-allowlisted text while comparing encoded packet bytes, exercise escaped strings and nesting, and assert non-reflecting failures. They do not establish compatibility with every installed client version or prove live provider totals. This first implementation has not been tested on private user logs.

These JSONL layouts are versioned client internals, not a stable provider billing API.

## Separate Codex lifecycle profile

`turns::parse_codex_turns(reader, &occurrence_key)` reads one caller-owned stream into private lifecycle and observation evidence. `turns::merge_turn_collections(&collections)` joins selected copies and partial histories before `daily_summary()` returns numeric UTC-day cohorts. The occurrence key must be nonzero. Different key namespaces cannot be merged, including empty streams. Native IDs, source text and the key are not exposed or serialized by this API.

Source profile 2 does not change `parse_reader`, its EOF behavior, token IDs, AICU packets or ledger source projections. This crate adds no path opener, source discovery, storage or upload. It supports provider-reported Codex runtime plus qualified observed response-token and requested-call subtotals. Complete `tokens` and dispatched `tool_calls` remain `None`; origin and provider account remain unknown, and terminal population coverage remains false.

Only completed-LF records contribute evidence. A partial tail is deferred even if it contains valid JSON. A source must first declare `session_meta.payload.id`; optional `session_id` stays unknown when absent and must match the ID when present. Each start must explicitly identify its own turn as `root_turn_id` to enter the root cohort. Declared parent, subagent, fork or inherited-history markers exclude the entire keyed thread, including late or cross-source declarations. Missing historical events cannot prove complete recovery history.

`completed` means provider-declared non-aborted terminal, including terminal errors, not successful task execution. Aborts form a separate cohort. Terminal epoch seconds assign the UTC day with one-second precision. Runtime uses the provider's independently reported elapsed milliseconds, including measured zero; it is not timestamp subtraction, CPU time or active work. Exact sums and eligible counts are exposed; an average is unavailable when eligible count is zero. Missing dates stay undated. Missing, negative or oversized durations remain unavailable.

Exact repeated selected evidence is inert. Conflicting terminals or explicit root identities fail before filtering. Null fields are not enriched from another record. Multiple distinct starts, an invalid or absent append timestamp, and mismatching valid coarse start coordinates make runtime unavailable. Start comparisons preserve fractional timestamp precision through nanoseconds; unsupported extra precision and leap seconds are not silently normalized. Selected-evidence equality is not proof that separate attempts cannot share the same values.

Each `RuntimeCohort` adds `observed_subtotals.response_tokens` and `observed_subtotals.requested_calls`. An `ObservedMetric` has `sum`, `turns_with_evidence`, and `observations`. Its observed subtotal mean divides the sum by distinct joined turns with evidence for that metric, not by response/call count or all cohort turns. The CLI serializes sums and numerators as decimal strings under `observedSubtotals`, with a null mean when no evidence exists and an always-null population mean. Explicit zero tokens are evidence; absent calls do not prove zero calls. Completed and aborted cohorts remain separate, and open/undated turns contribute no daily subtotal mean.

Top-level `token_usage_record` selects `usage.total_tokens` from zero through 10^12 inclusive and explicit thread/session/turn/root/response IDs. A response can contribute only when its reported thread/session match the file thread and its turn/root match an explicit root lifecycle. Each keyed `(thread, response ID)` retains the full selected binding; copies deduplicate and conflicting owners or totals fail. Raw `response_item` uses stamped turn ownership and counts function/custom/shell/search variants by `call_id`, or web/image variants by `id`, with no legacy fallback. The variants share call-ID or hosted-item namespaces respectively, so a conflicting kind or owner cannot create an extra count. Request presence does not prove dispatch or success. Cumulative counters, outputs, terminal tool items and nested compaction/Code Mode data do not contribute.

Missing ownership/totals remain unmeasured with fixed diagnostics. Incomplete bindings with both an established file-thread identity and an observation ID are retained, so a later copy cannot silently supply a missing value. Usage/calls before a file header remain unowned without entering the conflict maps. Malformed or duplicate selected fields fail. Cross-usage/lifecycle root conflicts are checked before late or cross-source ancestry exclusions. The provider omits usage records when a response lacks reported completion usage; raw calls can lack stamped ownership. These subtotals cannot establish complete turn accounting. [Daily turn measurements](../../docs/usage-turns.md) defines the output bases and pinned producer coverage evidence.

Successful parsed or merged collections contain at most 2,048 raw sources, 256 MiB consumed bytes, 100,000 physical records and 65,536 combined raw lifecycle/usage/supported-call observations. Copies and complete selected records missing fields consume these budgets before deduplication; unparsed non-LF tails remain deferred. `DailyTurnSummary.raw_observations` is the combined work count. A line is at most 1 MiB and nesting at most 64. Elapsed duration is at most 31 days; terminal seconds are at most 8,640,000,000,000. The response-token cap bounds the sum below `u64::MAX`; the private observation fold uses checked addition. Multi-file callers must also preflight their global budget, constrain remaining reads and merge incrementally; this library cannot bound arbitrary caller retention of separately parsed collections. `BufRead` may prefetch bytes beyond those consumed by the projection.

`TurnReadLimits::new(bytes, physical_records, raw_observations)` accepts zero through the profile ceilings; invalid limits fail before reading. `MAX_OBSERVATIONS` names the 65,536 combined ceiling. `parse_codex_turns_with_limits` applies the caller's remaining budget, and the original parser delegates with `TurnReadLimits::full()`. An exhausted byte or physical-record budget succeeds only at real EOF; identifying the first excess selected observation can consume that one bounded record before `turn_observation_limit`, without contributing it or reading the rest of the file. The [explicit-file CLI](../../docs/usage-local.md#inspect-observed-daily-turn-runtime) preflights combined file sizes, bounds each `BufReader` below its captured file length, and passes remaining budgets while merging incrementally. Its unpublished `sourceProfile: 2` and `rawObservations` keys replace `profileVersion` and `rawLifecycleRecords`. Ordinary usage collection, AICU, ledger, and complete-prefix formats remain unchanged.

Lifecycle fields and their persistence were checked against the pinned [Codex protocol](https://github.com/openai/codex/blob/4d205c7a4dc36b719679a0356a45b23133732265/codex-rs/protocol/src/protocol.rs), [rollout writer](https://github.com/openai/codex/blob/4d205c7a4dc36b719679a0356a45b23133732265/codex-rs/rollout/src/recorder.rs) and [turn timing implementation](https://github.com/openai/codex/blob/4d205c7a4dc36b719679a0356a45b23133732265/codex-rs/core/src/turn_timing.rs). The writer retains old headers on resume, so a missing session ID alone does not reject a current turn. Old starts without explicit root attribution remain unknown. Compatibility is field-based, not a promise about every installed release; synthetic fixtures do not qualify live provider totals or tamper resistance.
